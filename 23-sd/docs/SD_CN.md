# 23-sd — SD1 与 TF 卡

## 目标

1. 用 **20** 的 pinmux 把 io54–io59 接到 SD1（`IO_SEL=2`，与 U-Boot `k230_canmv_lckfb.dts` 的 MMC1 一致）
2. 打开 SD1 时钟，复位 DWC MSHC，3.3 V，识别时钟约 400 kHz
3. 按 `riscvboot` 的顺序发 CMD0、CMD8、ACMD41、CMD2、CMD3、CMD7，再 ACMD6 切 4-bit、时钟升到约 12.5 MHz
4. PIO 读扇区；对当前 LBA（0 除外）写入 `pat, pat+1, …`（256 循环），数据留在卡上

## 硬件

| 项 | 值 |
|----|-----|
| 控制器 | SD1 `0x91581000`（不是 eMMC 的 SD0 `0x91580000`）。SD1 没有 PHY |
| 时钟门 | `0x91100018` bit0/3/9–12/17–20 |
| 卡时钟 | `0x9110001c` bit14:12 写 1（÷2）。pll0/4 ÷ 2 约 **200 MHz** 进 SDHCI。能力寄存器 bit15:8 读出 `0x64`，这个字段不可用，分频不要按 100 MHz 算 |
| 跑卡时钟 | 识别约 400 kHz（`clk=0x000efa07`），4-bit 后约 12.5 MHz（`run=0x000e0807`） |
| 脚 | CMD io54，CLK io55，D0–D3 io56–io59，`IO_SEL=2` |
| HS 使能 | 用 SD1 前把 `0x91585008` 的 bit0 和 bit2 置 1，否则命令到不了卡 |
| 电压 | io50–io61 这一组 `MSC=0`，保持 3.3 V |

CLK 只开 OE、不上拉；CMD/DAT 开 IE+OE+上拉、DS=7。这和 U-Boot 里 TF 卡那一组 pad 相同。

## 菜单

```text
1  初始化（pinmux + CMD0..ACMD6）
2  读当前 LBA
3  跳到 LBA 256 并读
+ / - / 0    换 LBA 再读（0 回到扇区 0）
[ / ]        图案首字节 -1 / +1，提示符里的 pat= 就是当前值
w  把 pat, pat+1, … 写入当前 LBA，并留在卡上
4  dump io54–59
h  帮助
```

一扇区 512 字节，图案每 256 回绕，所以同样的 256 字节出现两遍。默认首字节 `a0`。`w` 不读回、不还原；核对用 `2` 或 `r`。

## 试验路径

1. 插卡 → `1` → `PASS init`。应看到 `hs=0x00000005`、`OCR` 的 bit31 和 bit30（sector）、`run=0x000e0807`
2. `2` 读 LBA 0。末两字节 `55 aa` 才是 MBR/GPT 保护扇区；本仓库试验卡上常见的是 `30 31 …` 和 `fe ff`，那是整扇区 `byte = (i & 0xff) | 0x30`，不是写坏
3. `3` 或 `+`/`-` 选一个可以覆盖的扇区（不要用 0）。`w` 后应 `PASS wrote`，再 `2`，开头是 `a0 a1 a2 … af`
4. `[` / `]` 改首字节后再 `w`、`2`，读出的第一个字节应跟着变
5. 在 LBA 0 上 `w` 会拒绝。不插卡时期望某条命令超时（`err -2`）

写会盖掉该扇区原来的内容。LBA 256 在 GPT 表之后、常见首分区 LBA 2048 之前，适合试写。

## 和 riscvboot 的差别

`riscvboot` 的 `sd_test()` 从 LBA 0 起写 2 KiB，而且不配 SD1 的 HS 垫和卡时钟。本课扇区 0 只读；其它 LBA 写入后留在卡上。写之前先复位 CMD/DAT：读完后缓冲还停在读方向，第一次 `CMD24` 会把 FIFO 里的数据丢掉，卡回报数据 CRC（`irq` bit21）和结束位（bit22）。复位后再写一次。
